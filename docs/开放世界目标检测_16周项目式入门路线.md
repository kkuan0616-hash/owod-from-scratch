# 从"只会跑 YOLOv5"到"能进组干活"：16 周项目式路线

> 面向对象：长春理工大学 计算机科学与技术 大二，零基础起步，已跑通过 YOLOv5 训练但不懂原理与参数。
> 依托课题：吉林省自然科学基金面上项目《面向智能感知系统的开放世界目标检测基础与方法研究》（2026.01–2028.06）。
> 投入假设：每周 10–12 小时（约每天 1.5 小时 + 周末半天）。有独立显卡最好；没有也能按"无显卡分支"走完全程。

---

## 0. 先用大白话看懂这个课题在干什么

普通目标检测（你跑过的 YOLOv5）是**闭卷考试**：考前告诉它"只考这 80 类"，它就只认这 80 类，遇到没见过的东西，它要么当成背景（**忽略错误**），要么硬说成某个像的已知类（**傲慢错误**）。

这个课题要做的是**开卷考试**：

1. **知道自己不知道**——检测已知类的同时，把"我不认识但像个物体"的东西圈出来，标成 `unknown`；
2. **问人**——把 `unknown` 交给用户/标注员，人挑几个感兴趣的类标一下；
3. **学会它，且不忘记**——用这几个新类做**增量学习**，模型变强的同时，原来会的类不能掉分（掉了就叫**灾难性遗忘**）；
4. **反复循环**——未知→标注→学习→再遇新未知，模型越来越"见多识广"，还能跑在算力有限的设备上。

一句话概括课题的三根支柱（任务书里的"研究内容"）：

| 支柱 | 要解决的事 | 典型技术手段 |
|---|---|---|
| ① 开放世界检测建模 | 已知/未知的**决策边界**怎么划 | 无监督目标性、知识解耦、能量分数、对比聚类 |
| ② 增量学习与新颖类发现 | 新类怎么**快速吸收**、旧类怎么**不打架** | 特征解耦、自适应分类器、对比学习、聚类发现 |
| ③ 抗遗忘与性能优化 | 参数一更新就**忘事**怎么办 | 元学习、示例重放、知识蒸馏、轻量化设计 |

**你要建立的第一个认知**：这不是"再训一个 YOLO"，而是"**检测器 + 一套未知判别机制 + 一套持续学习流程 + 一套评测协议**"。所以本科生完全有活干——评测、数据、复现、消融，全都是硬需求，而且不需要你先成为理论大师。

1. **每个阶段结束必须有一个"可展示物"**：一张图、一段视频、一个 GitHub 仓库、一份 4 页报告。

## 3. 阶段 A（第 1–4 周）：把 YOLOv5 从"会用"变成"懂"

> 阶段目标：能对着 `results.csv` 和 PR 曲线说出"模型哪里不行、为什么不行、下一步改什么"。
> 阶段交付：① 一个规范的项目仓库；② 自写的 mAP 评测脚本；③ 一份 6–8 页误差分析报告。

### W1｜把"能跑"升级成"能控制"

**做什么**
1. 建 GitHub 仓库 `owod-from-scratch`，目录按下面结构（这个结构会用到第 16 周）：
   ```
   owod-from-scratch/
   ├── data/            # 只放小样本，大数据集写下载脚本
   ├── configs/         # 训练配置（yaml）
   ├── scripts/         # train.sh / eval.sh / export.sh
   ├── src/             # 你自己的代码（评测、未知评分、增量学习）
   ├── experiments/     # 每次实验一个文件夹：配置+日志+权重链接+结论
   ├── reports/         # 周报、阶段报告、图
   └── README.md        # 记录"怎么复现"，不是"项目简介"
   ```
2. 数据集：**PASCAL VOC 2007/2012 取 3 类**（`person, car, dog`），约 3000 张图。理由：后面 OWOD 的标准协议就是 VOC 20 类，现在就用它，避免换数据集重学一遍。
3. 训练 3 组对照，只改一个变量：
   - A：`yolov5n`, img 640, epochs 50, batch 16
   - B：在 A 基础上 img 416
   - C：在 A 基础上 batch 8
4. **逐列读懂 `results.csv`**：`train/box_loss`、`obj_loss`、`cls_loss`、`metrics/precision`、`metrics/recall`、`metrics/mAP_0.5`、`metrics/mAP_0.5:0.95`、`x/lr0`。给每一列写一句话解释（写进 README）。

**必须搞懂（只这 5 个）**
- epoch / batch / iteration 的关系；学习率与 warmup；
- 为什么 loss 下降但 mAP 不涨（过拟合 / 标注噪声 / 阈值问题）；
- train loss 与 val loss 分叉意味着什么；
- 输入分辨率变化为什么同时影响精度和速度；
- 显存不够时，正确的降级顺序：降 batch → 降 img size → 换更小模型（不要一上来就改网络）。

**产出物**：仓库 + 3 组实验的 `results.csv` 曲线拼图 + 一页"参数—现象"对照表。
**验收**：能向同学解释"为什么 B 组 mAP 掉了 4 个点"。

> 无显卡分支：用 Kaggle/Colab 免费 T4，数据集挂载到 `/kaggle/working`，单次训练控制在 2 小时内（yolov5n + 3 类 + 50 epoch 足够）。

### W2｜拆开检测头：一次只改一个地方

**做什么**（读代码 + 手算 + 实验，三件事绑在一起）
1. 读 `models/yolo.py` 的 `Detect` 和前向输出，搞清楚输出张量形状 `(bs, 3, 80, 80, 5+nc)` 每一维是什么。
2. 读 `utils/loss.py`，用自己的话写出三项 loss 各管什么：**框回归（CIoU/GIoU）、目标性（obj）、分类（cls）**。
3. 手算一遍 IoU，然后手算一遍 NMS（拿 3 个重叠框，写出每一步）。
4. 做 3 个"破坏性实验"，每个都预测结果再验证：
   - 把 `conf-thres` 从 0.25 调到 0.5 → 精确率/召回率怎么变？
   - 把 `iou-thres`(NMS) 从 0.45 调到 0.7 → 密集场景框变多还是变少？
   - 关掉 mosaic 增强 → 小目标指标怎么变？

**必须搞懂**
- 正负样本分配（YOLOv5 的 shape/area 比例 + 中心先验）为什么决定"谁来学这个框"；
- anchor 是什么、AutoAnchor 在干什么（不必会推公式，要会说"它把先验框调到和你的数据分布匹配"）；
- 为什么 obj loss 是开放世界检测的"命门"（后面 ORE 就是拿 objectness 当未知分数的）。

**产出物**：一页手绘图（数据流：图→backbone→neck→head→decode→NMS→框）+ 3 个实验的结论。
**验收**：能画出"一个框从像素到输出"的完整链路，中间不缺环节。

### W3｜自己写一遍 mAP（这是分水岭）

**做什么**
1. 不调用 `val.py`，用 `src/eval/` 自己实现：
   - 按类别收集预测框与 GT，按置信度排序；
   - 逐个计算 TP/FP（IoU ≥ 0.5 且类别一致、且未被匹配过）；
   - 累积 precision/recall → 画 PR 曲线 → 算 AP（VOC 11 点法 + 全插值法都实现一遍，对比差异）；
   - 汇总 mAP@0.5 与 mAP@0.5:0.95（后者要在 10 个 IoU 阈值上重复）。
2. 与官方 `val.py` 的结果对齐，误差应 < 0.5 个点（对不上就一定是匹配逻辑写错了，这个 debug 过程本身就是最大收获）。
3. 额外产出一张**混淆矩阵**（预测类 × 真实类）和**按目标尺寸分组的 AP**（small/medium/large）。

**必须搞懂**
- AP 是"排序质量"的度量，不是"准确率"；
- 为什么 mAP@0.5:0.95 更严格、为什么论文里两个都报；
- 置信度阈值只影响 P/R 的取舍点，不影响 AP（AP 用全排序）——这一条能纠正 90% 初学者的误解。

**产出物**：`src/eval/` 可复用代码 + 对齐报告（你的数 vs 官方的数）。
**验收**：换一个模型（yolov5s）不用改代码就能评。

### W4｜写第一份"像样"的报告：误差分析

**做什么**
1. 从验证集里挑 **30 个错例**，分 5 类归档：漏检（小目标/遮挡/低对比度）、误检（背景纹理/相似类）、定位偏差、重复框、类别混淆。
2. 每类给 2 张可视化图（原图 + GT 绿框 + 预测红框 + 置信度）。
3. 提出 **3 条可验证的改进假设**，例如：
   - "小目标漏检多 → 提高输入分辨率到 1280 后 small-AP 应上升 ≥3 点"；
   - "person 与 dog 混淆 → 加入类别平衡采样或 focal loss 后混淆矩阵对角应更亮"。
4. 每周固定写"周报"（模板见第 9 节），发给带你的学长/老师。

**产出物**：`reports/W04_误差分析.pdf`（6–8 页）+ 一张"错误类型—占比—假设—验证方式"表。
**验收**：老师看完能说"这个学生知道模型错在哪"。

> **阶段 A 的心理建设**：这 4 周你会觉得"没做出新东西"。但正是这 4 周决定你后面是"调包的人"还是"能做实验的人"。绝大多数本科生卡在这里就放弃了——你熬过去就赢了一半。

## 4. 阶段 B（第 5–8 周）：进入开放世界（OWOD）

> 阶段目标：跑通并**评测**一个开放世界检测基线，能解释 U-Recall / WI / A-OSE 三个指标。
> 阶段交付：① OWOD 评测工具（你自己的）；② Task-1 复现结果表；③ 第一份技术报告。

### 先建立"任务协议"的概念（半天）

标准 OWOD 协议（VOC 20 类）：
- **Task 1**：已知 20 类中的 10 类（如 bird/aeroplane/... ），其余 10 类视为 unknown；模型要检测已知 + 把未知圈成 `unknown`。
- **Task 2/3/4**：每轮引入 5 个新类（人标注后），模型增量学习，**旧类不能掉**。
- 指标：
  - **mAP**：已知类检测精度（每轮都测，看掉多少）；
  - **U-Recall**：在固定已知类 recall 下，未知目标被召回的比例（衡量"能不能发现未知"）；
  - **WI（Wilderness Impact）**：未知目标被误判为已知类造成的精度污染；
  - **A-OSE**：绝对开集错误数（把多少个未知框错认成已知类）。

### W5｜三遍法读第一篇论文：ORE

论文：Joseph et al., *Towards Open World Object Detection*, CVPR 2021（ORE，这个方向的开山之作，必读）。

**三遍法**
- 第 1 遍（20 分钟）：只读标题/摘要/图 1/结论，回答"它解决什么问题、用什么招、效果如何"。
- 第 2 遍（2 小时）：读方法节，画出模块图，标出你看不懂的 5 个名词（大概率是：contrastive clustering、energy-based unknown、exemplar replay、RPN、unknown-aware objectness）。
- 第 3 遍（半天）：只读实验节，抄下它的**任务划分、超参、指标数值**，作为你的复现目标。

**产出物**：一张 A4 的论文拆解图（问题→假设→方法→实验→局限）+ 5 个名词的解释（自己查完写）。

### W6｜搭评测，跑 Task-1

**做什么**
1. 拿到 ORE 官方代码（或 OW-DETR 的 M-OWODB 数据划分），**先不训练**，用作者给的权重跑 Task-1 推理，得到一组数。
2. 用你自己 W3 写的评测逻辑，扩展到 OWOD 指标：
   - U-Recall：对 unknown 类，按置信度排序算召回；
   - WI：`(未知被误检为已知的数量 / 已知 GT 数量)` 之类的污染率，按论文定义实现；
   - A-OSE：统计未知框被错分到已知类的绝对数量。
3. 你的数 vs 论文的数，差多少、差在哪（数据划分？阈值？NMS？）。**这张对齐表就是你的第一份科研产出。**

> 说实话：这一步会非常痛苦（环境、依赖、数据格式、CUDA 版本）。给你的建议是**限定 3 天**，超过就换更简单的基线（YOLO 系 + 自己实现的未知评分），不要在环境上耗两周。

### W7｜亲手实现三种"未知分数"，做对比

在检测器输出的每个框上，算三种"陌生度"：
1. **objectness 分数**（最简单）：obj 高但分类置信度低 → 可能是未知；
2. **能量分数**：`E = -logsumexp(logits)`，能量越高越"不像已知"（ORE 用的就是这个思路）；
3. **特征距离**：框的特征与各类原型（类均值向量）的最小余弦距离。

在 Task-1 上画三者的 **U-Recall vs 已知 mAP 曲线**，选一个作为你后面的默认方案。

**产出物**：一张三线对比图 + 一段结论（"在 recall=0.8 时，能量分数比 objectness 的 U-Recall 高 X 点，原因是……"）。
**验收**：能说清"为什么 obj 高 + cls 低 ≈ 未知"这个直觉的合理性。

### W8｜写技术报告（第一份"能拿出手"的东西）

结构固定：问题 → 相关工作（3 篇够了）→ 方法（复现对象）→ 实验设置 → 结果表 → 失败案例分析 → 下一步。
长度 6–10 页，图表必须自己画。

**阶段 B 的心理建设**：到这里你已经能说"我在做开放世界目标检测"，而不是"我在学 AI"。这句话在保研面试/大创答辩里的分量，比多跑 10 个模型大得多。

## 5. 阶段 C（第 9–12 周）：增量学习与"不忘记"

> 阶段目标：把"新类加进来、旧类不掉分"这件事，用 4 种方法做一遍并量化对比。
> 阶段交付：方法对比表 + 遗忘曲线 + 消融实验。

### W9｜先定义"遗忘"

- 任务序列：Task1(10 类) → Task2(+5) → Task3(+5) → Task4(+5)。
- 指标：每轮结束后测**所有已见类**的 mAP，画"轮次—mAP"曲线；定义 **遗忘量 Δ = 首次学会时的 mAP − 最后一轮的 mAP**。

**产出物**：一张"什么都不做（直接 finetune）"的基线曲线——这条曲线会掉得很惨，它就是你要打败的敌人。

### W10｜四种抗遗忘策略，逐个实现

| 方法 | 一句话原理 | 实现难度 | 预期效果 |
|---|---|---|---|
| Finetune（基线） | 只在新数据上继续训 | ★ | 遗忘最严重 |
| LwF | 用旧模型对旧类的输出当"软标签"约束新模型 | ★★ | 中等 |
| EWC | 给重要参数加"不许乱动"的惩罚（Fisher 信息） | ★★★ | 中等，实现易错 |
| Replay（示例回放） | 存每类几十张旧图，新轮次混着训 | ★★ | 通常最好 |
| Replay + 蒸馏 | 回放 + 旧模型 logits 蒸馏 | ★★★ | 最好，也最像论文做法 |

建议顺序：Finetune → Replay → LwF → Replay+蒸馏。**EWC 可选**（时间不够就跳过，它在这个任务上通常不如回放）。

### W11｜调通 Task2–4 + 记录"新类发现"能力

- 每轮加入新类时，先让模型"自由发现"（不给标签），再用聚类/对比学习把新类分出来（对应课题研究内容②的"新颖类发现"）。
- 记录两个数：新类**首次**出现的 mAP（学得快不快）、旧类**遗忘量**（忘得多不多）。这两个数是一对矛盾，你后面所有改进都在调这个 trade-off。

### W12｜消融实验（学会"证明有用"）

固定一个改进点，做 3–5 组消融：去掉模块 / 换超参 / 换回放比例（如每类 20/50/100 张）。
**产出物**：一张标准消融表（每行一个配置，列为 mAP、U-Recall、遗忘量、训练时间）。

## 6. 阶段 D（第 13–16 周）：做出"你自己的那一点点新东西"

> 目标不是发顶会，而是**做出一个可以被验证的小改进**，并写成大创申报书/技术报告/竞赛作品。

### 三个可落地的选题（按难度从低到高，选一个）

**选题 1（推荐，最容易出结果）：未知分数的融合**
- 思路：`score = α·objectness + β·energy + γ·(1 − 特征相似度)`，用验证集网格搜索 α/β/γ。
- 为什么可行：不需要改网络结构，纯后处理，1 周能做完，且大概率比单一分数好。
- 验收：U-Recall 在同等 mAP 下提升 ≥2 点，且有消融表。

**选题 2：类别均衡的示例回放**
- 思路：回放时按"类别难度/遗忘速度"分配配额（遗忘快的类多存几张），而不是每类均分。
- 为什么可行：只改采样器，代码量 100 行以内，故事完整（"针对长尾遗忘"）。

**选题 3：轻量化（对应课题研究内容③）**
- 思路：把 backbone 换小（yolov5n / MobileNet），测"精度—参数量—推理时延"三角，给一张帕累托图。
- 为什么可行：工程活，适合作为大创的"应用落地"章节。

### W13–W16 排期
- W13：实现 + 单任务验证（先在 Task1 上调通）；
- W14：全任务序列跑通，收集 3 个 seed 的结果（**一定要多 seed**，否则结论不可信）；
- W15：消融 + 画图（折线/柱状/帕累托），写 4 页技术报告；
- W16：整理成 **大创申报书**（或挑战杯/计算机设计大赛作品书）+ 15 页答辩 PPT + 3 分钟 demo 视频。

**成果落点建议**（按性价比排序）：
1. **国家级/省级大学生创新创业训练计划**（2026 年春季申报，正好接上课题 2026.01 启动）；
2. 校级/省级竞赛（挑战杯、中国计算机设计大赛人工智能类）；

## 7. 知识补丁清单（按需查阅，**不要通读**）

### 7.1 深度学习最小集（约 12 小时，第 1–2 周穿插）
- 3Blue1Brown《神经网络》系列（4 集，建立直觉）；
- 李沐《动手学深度学习》只读：线性回归 → softmax 回归 → 多层感知机 → 反向传播 → 卷积神经网络（**跳过** RNN/注意力/优化器数学推导）；
- 必须能回答：什么是梯度下降、什么是过拟合、batch size 影响什么、学习率太大/太小各是什么现象。

### 7.2 目标检测最小集（约 10 小时，第 2–3 周）
- 一张图看懂：two-stage（Faster R-CNN：RPN + RoI）vs one-stage（YOLO/FCOS）；
- 必懂概念：IoU、anchor、正负样本分配、NMS、mAP、FPN；
- 综述（选读，只读前半）：*Object Detection in 20 Years: A Survey*。

### 7.3 开放世界检测（第 5–8 周，按序读）
1. **ORE** (CVPR'21)：开山之作，必读，必复现；
2. **OW-DETR** (CVPR'22)：换成 DETR 框架，同时发布了 M-OWODB / S-OWODB 数据集划分（**你要用它的划分**）；
3. **PROB** (CVPR'23)：把"不确定性"引入未知判别，思路清晰；
4. **CAT** (ICCV'23)：级联式"定位+识别"，工程性强；
5. 综述：*Open World Object Detection: A Survey*（用来查漏，不要从头读到尾）。

### 7.4 增量学习（第 9–12 周）
- 必读 3 篇经典：**LwF**（蒸馏抗遗忘）、**EWC**（参数重要性）、**iCaRL**（exemplar + 分类器校正）；
- 选读：**DER**（把增量学习当特征回放，思路新）；
- 关键概念：灾难性遗忘、稳定性—可塑性权衡、样本回放、知识蒸馏、原型分类器。

> **读论文的正确姿势**：每篇只允许自己花 3 小时，产出"一页纸"：问题 / 关键招 / 我能不能用在当前代码里（能/不能，为什么）。读不懂的公式先跳过，等实验撞上了再回来看——那时候你才读得懂。

## 8. 常见坑（都是本科生真实踩过的）

1. **在环境上耗两周**：用 Docker 镜像或直接 Kaggle Notebook，环境问题设 3 天硬上限。
2. **只跑不留痕**：不记录 seed、配置、commit hash 的实验等于没做。每次实验一个文件夹。
3. **拿单次结果下结论**：至少 3 个 seed，报均值±方差。审稿人/老师第一个问的就是这个。
4. **一上来改网络结构**：先复现、先对齐数字，再谈改进。改结构 90% 的收益来自超参和数据。
5. **数据集贪大**：COCO 全量在 8G 显存上跑不动，前期一律 VOC 子集。
6. **把"训练 loss 下降"当成功**：只看验证集指标。
7. **不看错例**：误差分析是性价比最高的"改进来源"，没有之一。
8. **不敢问**：组里学长学姐踩过的坑，能省你两周。每周汇报时明确说"我卡在哪、我试过什么"。
9. **追求"读完再动手"**：你会永远在读。用项目倒逼学习。
10. **不写周报**：写了才知道自己这周其实啥也没干——这是好事。

## 10. 怎么和老师/课题组相处（这部分决定你能不能真的进组）

1. **第一次沟通就给"可交付"**：不要说"我想学 AI"，要说"我用 VOC 3 类复现了 YOLOv5，mAP 0.xx，做了一份误差分析报告，能否让我从**数据与评测**这块入手？"
2. **主动领"脏活"**：数据清洗、划分校验、评测脚本、跑对比实验——这些是组里最缺人、也最容易让你快速理解全局的活。
3. **每周固定汇报**（哪怕只有 5 行），让老师知道你在推进；**不要憋大招**。
4. **明确边界**：本科生的贡献通常是"实验 + 消融 + 图"，论文署名按贡献谈，不要一开始就承诺"发一篇"。
5. **要资源要具体**：不说"给我算力"，说"我需要一张 8G 以上显卡跑 Task-2 的 3 个 seed，约 40 GPU 小时"。
